Rivet — нативный HTTP‑клиент для API. Интерфейс рисуется на GPU движком редактора Zed, без Electron. Rivet понимает OpenAPI и Postman‑коллекции, выполняет скрипты pm.*, сверяет ответы со схемой, поднимает моки и показывает, куда ушла каждая миллисекунда. Ваш ИИ‑ассистент тоже им пользуется, через MCP.

    ⌘O импорт спецификации
    
        
    Спецификация задаёт правила
    
        
    Откройте OpenAPI 3.x, Swagger 2.0, Postman‑коллекцию или HAR, и запросы разложатся по папкам. Каждый ответ Rivet сверяет со схемой: показывает отсутствующие поля, неверные типы и значения вне enum, а по клику ведёт к нужной строке.
    
        
      
          
    • «Generate from schema» собирает тело запроса по схеме
      • 
          
    • При наведении на поле JSON всплывает его описание из схемы
      • 
          
    • ⌘R обновляет коллекцию из исходного файла
      • 
          
    • Auth «Inherit from spec» сам берёт токен из окружения
      • 
        
    
      
    
      
    
    

    
    
      
    
        
    
          
    pm.* · Boa JS
    
          
    Скрипты и тесты в стиле Postman
    
        
    
        
    
          
    Pre‑request меняет запрос и переменные перед отправкой, Post‑response разбирает ответ и прогоняет тесты. API тот же, что в Postman, поэтому скрипты из импортированных коллекций работают сразу. Внутри Boa, движок JavaScript на чистом Rust.
    
          
      
            
    • Результаты во вкладках Tests N/M и Console
      • 
            
    • Ошибка в pre‑request останавливает отправку и показывает строку
      • 
            
    • Сниппеты в один клик: статус 200, время ответа, поле в ответе
      • 
          
    
          
    pm.environmentpm.collectionVariablespm.variablespm.requestpm.responsepm.testpm.expecttests[…]postman.*console.log
    
        
    
      
    
      
    
    

    
    
      
    
        
    WireMock · Docker
    
        
    Мок‑сервер в один клик
    
        
    Сохраните ответ как пример: закладка в заголовке ответа кладёт его рядом с запросом. Потом «Запустить мок» в меню коллекции. Rivet находит Docker, поднимает WireMock и отвечает вашими примерами по методу и пути. Фронтенд можно писать, пока бэкенда ещё нет.
    
        
      
          
    • Нужный пример выбирается заголовком x-mock-response-name или x-mock-response-code
      • 
          
    • Окружение «Mock» направляет baseUrl на мок
      • 
          
    • Новые примеры подхватываются без перезапуска, при выходе контейнеры останавливаются
      • 
          
    • Моки, запущенные в окне и через MCP, видят друг друга
      •

    ws:// · wss://
    
          
    WebSocket рядом с HTTP
    
        
    
        
    
          
    Подключение, отправка Text, JSON и Binary (hex), ping и шаблоны сообщений. Лента входящих и исходящих с фильтром, временем и размером. Заголовки и auth рукопожатия настраиваются как у обычного запроса.
    
          
      
            
    • WS‑запросы сохраняются в коллекции и попадают в историю
      • 
            
    • Видны статус 101 Switching Protocols, время рукопожатия и счётчики сообщений

    Timeline
    
        
    Видно, куда ушла каждая миллисекунда
    
        
    Timeline раскладывает запрос на DNS, Connect, TLS, TTFB и Download и показывает весь путь редиректов: откуда, куда, с каким статусом и за сколько.
    
        
      
          
    • HTTP/2 через ALPN, h2c для http://, ручной выбор версии
      • 
          
    • gzip, deflate и br; HTTP/1.1 и HTTP/2 через CONNECT‑прокси
      • 
          
    • Редиректы, таймаут и проверка SSL настраиваются для каждого запроса

    ⌘E следующее окружение
    
          
    Production под защитой

    • Секреты скрыты точками и открываются по клику
      • 
            
    • Переменные коллекции и окружения плюс встроенные {{$uuid}}, {{$timestamp}}, {{$randomInt}}

    Вопросы
    
      
    Коротко о главном
    
    
    
    
    
      
    Rivet правда бесплатный?
    Да. Исходный код открыт на GitHub. Платных версий, подписок и аккаунтов нет.
    
      
    Где хранятся мои коллекции и токены?
    У вас на диске, в одном файле project.json: на macOS в ~/Library/Application Support/Rivet, на Windows в %APPDATA%\Rivet, на Linux в ~/.local/share/Rivet. Рядом лежат история и журнал MCP.
    
      
    Rivet куда‑то отправляет мои данные?
    Нет. В сеть Rivet ходит только за вашими запросами и за проверкой обновлений на GitHub. Проверку можно выключить: «Настройки → Обновления».
    
      
    Получится переехать с Postman?
    Да. Rivet импортирует коллекции Postman v2.x вместе со скриптами и выключенными авто‑заголовками, а pm.* работает так же. Экспорт обратно в Postman v2.1 тоже есть.
    Пока не поддерживаются pm.sendRequest, require и CryptoJS, а также скрипты уровня коллекции.
    
      
    macOS пишет, что не может проверить разработчика
    Rivet пока не подписан сертификатом Apple. Выполните один раз xattr -dr com.apple.quarantine /Applications/Rivet.app или откройте «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть». Обновления, которые Rivet ставит сам, этого не требуют.
    
      
    Как обновляться?
    Rivet проверяет GitHub Releases через 5 секунд после запуска и раз в 6 часов. На кнопке над «Настройками» появится точка. «Скачать» загрузит архив и сверит SHA‑256, «Перезапустить и обновить» заменит файлы. Проект и настройки при этом не трогаются.
    
      
    Что нужно для моков?
    Установленный Docker. Rivet сам найдёт его и запустит WireMock (wiremock/wiremock). Движок, порт и образ меняются в «Настройки → Моки».
    
      
    Что такое MCP?
    Model Context Protocol — открытый протокол, через который ИИ‑ассистенты подключают внешние инструменты. Rivet отдаёт ассистенту коллекции, окружения, отправку запросов и моки. Права настраиваются в «Настройки → MCP».
